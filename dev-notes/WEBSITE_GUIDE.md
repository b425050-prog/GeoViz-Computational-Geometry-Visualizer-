## 2. HTML forms are the interaction layer

Each state-changing control is a normal form. The server validates it and returns a redirect or an error page. This is compatible with C++-only application logic.

Illustrative template structure; `{{...}}` below denotes values your chosen view system must safely supply, not literal Drogon template syntax:

```html
<form method="post" action="/posts/example/reaction">
  <input type="hidden" name="csrf_token" value="{{escaped_csrf}}">
  <input type="hidden" name="request_key" value="{{escaped_request_key}}">
  <button name="state" value="like" type="submit">Like</button>
  <button name="state" value="dislike" type="submit">Dislike</button>
  <button name="state" value="neutral" type="submit">Clear reaction</button>
</form>
```

The actual post ID is generated by the server, not hardcoded. Avoid GET links for mutations. Browser validation is a usability improvement; server validation remains authoritative.

## 3. Media presentation

Use `<img>` with meaningful alternative text and bounded responsive dimensions. Use `<video controls preload="metadata">` with an authorized source route and suitable captions/subtitles where assets provide them. An HTML video element can seek/play without JavaScript.

The private media route must handle supported Range requests and authorization together. Do not expose a public static path as an easy workaround for playback. A denied byte-range request must not leak restricted bytes. Proper content type, length, cache policy and range validation are part of the media implementation.

Do not claim to measure watch duration. The specified view metric is a deduplicated authorized content-page request; media range fetches are not extra views.

## 4. Age-restricted content

Show a simple age badge on content that the requester may see. Use benign sample media for mature-topic labels. An ineligible requester sees a generic unavailable/restricted message, not the hidden thumbnail/caption under a CSS blur.

Filter feeds, search, profiles and APIs before serialization. Authorize direct media and thumbnail requests independently. A creator or administrator is not automatically allowed to bypass eligibility. An eligible analyst still needs content-review permission.

Use an injectable clock and the calendar rule in [contracts](../docs/CONTRACTS.md). Account creation time and birth date answer different questions: an adult can have a new account, and an old account can belong to an ineligible user.

## 5. Upload pipeline

Accept only a small approved set of media types and sizes. Validate content signatures and dimensions using vetted C++-accessible facilities; do not trust filename extensions or the browser's MIME header. Generate storage names and prevent user-controlled filesystem traversal.

Write uploads to a staging area, validate, then publish an authorized media reference. Avoid serving a partially written file. Failed validation removes staging data under a bounded cleanup policy. Decide how database commit and final file placement recover after a crash; a missing-media state is better than silently serving another file.

For the first slice, seed curated local media. Creator upload support follows once access and file handling tests exist. No remote URL import is required.

## 6. Visual design and accessibility

Use a consistent dark palette with readable text, restrained accent colours and clear focus outlines. CSS grid/flexbox supports responsive cards without JavaScript. Keep form labels visible; placeholders are not labels. Errors should identify the field and explain the correction.

Respect `prefers-reduced-motion` for CSS decoration. Do not animate essential text or make information available only on hover. Use semantic navigation/headings, useful alternative text, sufficiently large controls and keyboard-accessible forms. Empty feeds, denied access and failed submissions need intentional layouts too.

There is no browser live-update promise in the first release. Users refresh/navigate pages after actions; the C++ desktop console independently polls authorized analysis results.

## 7. Counting and policy integrity

One current reaction row represents state; events represent real transitions. Repeated identical submissions do not increase counts. Multiple report categories remain separate review information but are collapsed where the detection contract defines unique reporting activity.

An account cannot choose its own creation time, role, dataset or real-observation location from a hidden form. Hidden fields are editable by the client and must never be treated as trusted metadata.

## 8. Verification checklist

Use a browser with JavaScript disabled. Register, log in/out, inspect photo/video posts, change a reaction, comment, report and paginate. Then repeat with an ineligible account, a different creator, an expired session and direct media URLs. Inspect the durable event query to ensure the UI's actions correspond to the intended counts.
